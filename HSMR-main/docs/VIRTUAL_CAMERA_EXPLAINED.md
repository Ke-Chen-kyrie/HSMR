# HSMR 虚拟相机 — 从零讲清楚

## 你为什么困惑？

因为你把"虚拟相机"想成了一台真正的摄像头。它不是。

**虚拟相机 = 一套数学公式**，用来回答一个问题：

> 「神经网络生成了一个 3D 人体，该把它放在画面里什么位置、什么距离，投影到 2D 才能和图像里的人重合？」

把它想成 **Blender 里的 Camera 对象**：你有个 3D 人体模型，需要摆一台数学相机，调整人体相对相机的位置，让渲染结果和照片对上。虚拟相机就是干这个的。

---

## 第一性原理：针孔相机

真实相机（针孔模型）的投影公式：

```
u = fx × (X / Z) + cx
v = fy × (Y / Z) + cy
```

- `(X, Y, Z)` = 物体在相机坐标系中的 3D 位置
- `fx, fy` = 焦距（像素单位）
- `cx, cy` = 主点（图像中心）
- `(u, v)` = 投影到图像上的 2D 像素坐标

任何一个 3D 点 `[X, Y, Z]`，除以其深度 `Z`，乘以焦距，加主点偏移，就得到它在图像上的像素位置。

## HSMR 具体怎么做

### 第 1 步：输入 → 输出

输入：256×256 的 RGB 人体裁剪图
输出：三样东西

```
poses  [1, 46]     ← 人体姿态（关节旋转角度）
betas  [1, 10]     ← 人体体型（高矮胖瘦）
camera [1, 3]      ← [scale, tx, ty]（弱透视相机参数）
```

### 第 2 步：scale → tz（深度）

这是最关键的一步。网络不是直接输出深度 Z，而是输出一个 `scale`。

为什么？因为从单张 RGB 图无法知道「这个人是矮且近」还是「高且远」。
网络只能知道「这人占了图像多大比例」→ 这就是 scale。

```python
tz = 2 × 5000 / (256 × scale + 1e-9)
```

**直觉**：
- 人在图里很大 → scale 大 → tz 小（人离相机近）
- 人在图里很小 → scale 小 → tz 大（人离相机远）

**为什么是 5000？** 这是 HMR 系列论文的经验值。SMPL/SKEL 人体模型在 rest pose 时约 1.8m 高。在一个 256×256 的裁剪图中，人通常占 ~60-80% 高度。用 f=5000 配合这个人体尺度和图像尺寸，得到的人体投影大小刚好合适。这是**约定俗成**的，不是从相机标定来的。

### 第 3 步：放置人体

```python
camera_translation = [camera[1], camera[2], tz]
                    = [tx,           ty,         2×5000/(256×scale)]
```

这个向量告诉你**人体根节点（骨盆附近）在相机前方什么位置**：

```
相机原点 (0,0,0)
    │
    │  camera_translation = [tx, ty, tz]
    ↓
人体根节点
```

- `tx`：人体在图像中的水平偏移（tx > 0 → 人体偏右）
- `ty`：人体在图像中的垂直偏移（ty > 0 → 人体偏下）
- `tz`：人体到相机的距离（tz 越大 → 人在图里越小 → scale 越小）

### 第 4 步：投影

```python
joints_44_camera = joints_44_body + camera_translation
# 例如：人体头部关节在 camera 坐标 = [0.0, 0.38, 0.0] + [0.05, 0.02, 5.0]
#                              = [0.05, 0.40, 5.0]

u = 5000 × 0.05 / 5.0 + 128 = 178   # 头部在图像偏右
v = 5000 × 0.40 / 5.0 + 128 = 528   # 头部在图像上方？不——
```

**等一下。** `v = fy × Y / Z + cy`。body +Y = 上（头在上方），camera +Y → v 增大 → 图像下方。所以头（body +Y）投影到图像里的位置反而更靠下？

这就是为什么 pyrender 渲染时有一个**180° 绕 X 轴旋转**：

```
py_renderer/__init__.py:332-335
rot = rotation_matrix(180°, [1,0,0])
mesh.apply_transform(rot)
```

`R_180X` = diag(1, -1, -1)：
- Y 翻转：body +Y（头）→ -Y → 投影后 v 减小 → 头在图像上方 ✅
- Z 翻转：body +Z（前）→ -Z → 在 OpenGL 相机前方 ✅

**所以虚拟相机在"纯 HSMR 数学"和"pyrender 渲染"之间有一个 YZ 翻转。** 这是为了让 body 坐标系（+Y=上, +Z=前）适配 OpenGL 渲染管线。

## 具体数值示例

假设网络对某个人的输出是：

```
camera = [scale=0.025, tx=0.03, ty=-0.05]
```

计算：

```
tz = 2 × 5000 / (256 × 0.025) = 10000 / 6.4 ≈ 1562
camera_translation = [0.03, -0.05, 1562]
```

人体根节点在相机前方 1562 个单位处。投影：

```
u_root = 5000 × 0.03 / 1562 + 128 ≈ 224
v_root = 5000 × (-0.05) / 1562 + 128 ≈ -32 + 128 = 96
```

根节点投影到 patch 的 (224, 96) 处。

**tz=1562 是什么意思？是 1562 米吗？** 不是。这里的"单位"是**焦距归一化单位**。因为 f=5000 是像素单位，所以 tz 也是像素量纲。人体模型本身的尺度（约 1.8 单位高）配合 f=5000、图像 256×256，才得到合理的投影。这些单位不是米，需要通过真实深度传感器来标定。

## 虚拟相机 vs 真实相机

| | HSMR 虚拟相机 | RealSense 真实相机 |
|---|---|---|
| 物理存在 | ❌ 不存在 | ✅ 存在 |
| 焦距 | 固定 5000 | CameraInfo.K[0] |
| 主点 | patch 中心 (128,128) | CameraInfo.K[2],K[5] |
| 深度 | 从 scale 反算（不是米） | 传感器测量（米） |
| 用途 | 让 3D 人体投影对齐 2D 图像 | 测量目标在空间中的真实位置 |
| 畸变 | 不考虑 | 有（需校正或使用 rectified 图） |

## 一句话总结

**虚拟相机就是 Blender 里那台数学 Camera**。

你跟 HSMR 说「我在 256×256 的图里看到一个人，大概占了图 70% 的高度，偏左一点」。

HSMR 回答：
- 「OK，那我生成一个 3D 人体，」
- 「放在相机前方 1562 个单位处（tz），」  
- 「稍微往左挪一点（tx），」
- 「然后投影到 256×256 上，」
- 「你看——跟原图里的人对上了吧？」

这就是虚拟相机做的全部事情。它不告诉你「人离机器人 3.2 米」——它只是负责「画得对」。
